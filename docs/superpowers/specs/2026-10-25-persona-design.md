# persona — дизайн сайта (черновик)

Статус: **черновик**, решения на 2026-10-25. Предварительный дизайн согласован; вкладки Contact, About me,
Metta Corpse и Études ещё дорабатываются (см. «Открытые задачи»). Реализацию не начинали.

Кликабельный прототип со всеми решениями: `.superpowers/brainstorm/1382-1792925805/content/prototype-v20.html`
(папка в `.gitignore`; открывается через визуальный компаньон brainstorming с `--project-dir` = корень репозитория).
Картинки в прототипе взяты из `D:\Unity Projects\ui-line-chart\Packages\com.sxm-tools.ui-line-chart\Promo~`.

## Зачем

- Личный сайт-портфолио `sxm-sxpxxl`, у которого сейчас главный раздел — SXM Tools.
- Первые посетители приходят с Unity Asset Store и из ролика UI Line Chart, поэтому сайт открывается на SXM Tools.
- Место для сообщений об ошибках, вопросов и идей по инструментам и публичный список известных проблем.
- Анти-цель: «узнаваемый нейро-стиль» (карточки в рамках, мелкий серый текст, плашки с полосками) и копирование
  чужих сайтов. Референс xsgames.co дал только строгость, крупную типографику и частично раскладку.

## Адрес, хостинг, технологии

- Адрес: `https://sxm-sxpxxl.github.io/` — в корне, поэтому репозиторий на GitHub называется `sxm-sxpxxl.github.io`
  (сайт пользователя). Переименован из `sxm-sxpxxl/persona` 2026-11-01, локальный `origin` обновлён; со старого
  адреса GitHub перенаправляет. Локальная папка остаётся `persona`, название «persona» живёт в шапке
  (`persona=sxm-sxpxxl`). Чтобы на GitHub было понятно, что это: описание и темы в About, ссылка на сайт в поле
  Website (после запуска сайта), закрепить в профиле.
- Сразу после переименования GitHub сам включил Pages из ветки `main` и через Jekyll опубликовал этот документ
  по адресу сайта. Публикация снята 2026-11-01, источник Pages — «GitHub Actions»: пока нет сборки на Zola,
  ничего не публикуется.
- Сборка: **Zola**, публикация на GitHub Pages через GitHub Actions.
- Вкладки — отдельные страницы Zola со своими адресами, но переключаются без перезагрузки (скрипт подменяет
  содержимое и адрес), чтобы музыка и фон не обрывались. Прямые ссылки и поисковики работают как обычно.
- Форма обратной связи: своя, на сайте; отправка через Cloudflare Worker (бесплатный тариф) с токеном Notion
  и защитой Cloudflare Turnstile; запись попадает в базу «Входящие» со статусом New.
- Known issues и FAQ: публичные базы Notion; GitHub Actions раз в сутки и по кнопке забирает их через API Notion
  и пересобирает сайт. Интеграция Notion видит только эти две базы, но не «Входящие».

## Общая оболочка

- Только тёмная тема. Светлую пробовали — не подошла.
- Фон `#131417`; текст `#EEF0F5`; приглушённый `#969BA8`; линии `#25272e`.
- Шрифты (Google Fonts, есть кириллица): **Geologica** — заголовки и текст, **JetBrains Mono** — подписи, табы-метки,
  терминальные элементы.
- Шапка: слева `persona=sxm-sxpxxl` (JetBrains Mono, «persona=» приглушено, мигающий курсор-блок), справа табы
  `SXM TOOLS · METTA CORPSE · ÉTUDES · CONTACT · ABOUT ME` и переключатель `sound=off`. Значок SXM Tools в шапке
  не используется — он принадлежит только SXM Tools.
- Активный таб «горит» цветом своего раздела (неоновая трубка). Оболочка нейтральная, у каждого раздела свой стиль.
- Подписи разделов слева: `NN / раздел`, где NN — номер вкладки (01 SXM Tools … 05 About me).
- Кнопки действия — «неоновые трубки»: капсула с обводкой, при наведении светится.
- Подпись кнопки или ссылки никогда не переносится внутри. Если ряду кнопок не хватает ширины, на следующую строку
  уходит кнопка целиком. «Write to me →», LinkedIn и GitHub на About me стоят в один ряд на всех экранах: на узком
  ряду (< 360 px, телефон) кнопка и ссылки чуть плотнее (поля кнопки 16 px вместо 24), и всё помещается от ~330 px;
  ещё уже — обе ссылки вместе уходят под кнопку.
- Страница всегда не ниже экрана; фон (и живой холст) тянется до низа.

### Запуск сайта

Показывается при первом заходе за визит; клик или клавиша пропускают; при «уменьшить движение» — без анимации.
1. Пусто, в шапке `persona=` и курсор; затем по буквам печатается `sxm-sxpxxl`.
2. По центру — журнал терминальной сессии:
   `> session  connecting as sxm-sxpxxl … ok`, `> tabs  sxm-tools · metta-corpse · études · contact · about-me ok`
   (имена дописываются по мере того, как табы загораются с мерцанием), `> sound  off  click sound=off to turn it on`,
   `> open  /sxm-tools … ok`.
3. Журнал растворяется, загорается SXM Tools, страница выплывает. Всего около 4,3 с (можно сжать до 3).
   При прямой ссылке на другую вкладку запуск заканчивается на ней.

### Музыка

- У SXM Tools, Metta Corpse и Études свои темы, у Contact и About me общая служебная. Смена вкладки — кроссфейд ~1,6 с.
- По умолчанию звук выключен (`sound=off`), выбор запоминается. Треки грузятся только при включённом звуке,
  готовятся как бесшовные петли. Треки — за автором; в прототипе синтезированные заглушки.

### Телефон

- Шапка: `persona=…` и `sound=off` сверху, ниже строка табов.
- Меню — три вкладки по кругу: предыдущая прижата к левому краю, текущая по центру, следующая к правому краю,
  названия целиком. Нажатие на соседнюю «прокручивает» полосу (~0,4 с), и она становится текущей; остальные ждут
  за краями. По кругу: у SXM Tools слева About me, у About me справа SXM Tools. Отвергнуты: пустой край у первой
  и последней вкладки и строка табов, которая листается вбок. На экранах уже ~340 px зазор между вкладками почти
  исчезает — там уменьшить шрифт.
- Полноэкранный кадр на телефоне занимает экран телефона (в прототипе — рамку), прокрутка под ним замирает.
- Телефон горизонтально (в прототипе — режим «Телефон горизонтально», экран 800 × 370): по ширине включается
  раскладка компьютера. Fullscreen и журнал запуска помещаются.
- Ширина 700–880 px (телефон горизонтально, планшет вертикально): пять табов компьютера не влезают (им нужно
  от ~880 px), поэтому шапка остаётся в одну строку высотой 62 px: слева `persona=…`, посередине меню из трёх
  вкладок по кругу (как на телефоне), справа `sound=off`.
- Низкие экраны (на сайте — `@media (max-height: 500px)`): логотип 260 px вместо 520, отступы сверху меньше —
  на первом экране помещаются логотип, лид и заголовки принципов.
- Всё в одну колонку, подписи `NN / …` над разделами. Карусель — свайпом и точками (стрелок нет).
- У продуктов скрыты миниатюра и надпись `details`; у Known issues скрыты колонки Product и Version.

## SXM Tools (01)

- Цвета логотипа по ролям: бирюзовый `#28D5E4` — интерфейс (активный таб, номера, рамки), оранжевый `#FB7D22` —
  действия (главные кнопки, стрелки и точки карусели, цена).
- Вместо текстового заголовка — готовый логотип **со слоганом**, по центру правой колонки. Нужна выгрузка из Affinity
  с прозрачным фоном (свечение полупрозрачное), плотная обрезка, ширина ~1200 px. Сейчас — вырез из
  `sxm-tools-logo.png` (лочап 593×346 px на фоне `#131417`) с имитацией прозрачности.
- Под логотипом, по левому краю: «I make tools for Unity developers.» + приглушённо «In each one, I try to follow
  three principles:».
- Принципы в три колонки с тонкими вертикальными разделителями:
  - Intuitive — Easy to understand, with nothing on screen that does nothing.
  - Attentive — It talks to you through hints, notices and clear errors.
  - Fast — It respects your time and your hardware: no waiting, no wasted work.
- `01 / tools`: список продуктов с горизонтальными разделителями; раскрыт всегда один (по умолчанию UI Line Chart),
  закрыть открытый, не открыв другой, нельзя — поэтому у раскрытого нет кнопки и подсветки.
  - Свёрнутый: номер (с отступом от края), миниатюра, название и строка описания, справа `details` + круглая кнопка
    с шевроном; при наведении подсвечивается вся карточка (ширина = разделителям), миниатюра и кнопка — оранжевым.
  - Раскрытый: описание, бейджи-«щиты» как в README (`version | 0.9.14`, `unity | 6.0+`, `price | $19.99` — цена
    оранжевая; у UI Factory ещё `license | MIT`), кнопки (UI Line Chart: Asset Store + Docs; UI Factory: GitHub + OpenUPM),
    карусель промо-кадров.
  - Отдельных страниц продуктов нет — подробности в сторе, документации, на GitHub.
  - Карусель: кадр в мягкой рамке (едва заметная граница, скругление 10 px, многослойная тень без смещения);
    стрелки — приглушённые оранжевые кружки снаружи кадра, вся боковая полоса кликабельна; точки по центру под кадром;
    подписей нет (заголовок есть на кадре); клик по кадру — на весь экран (скругление 16 px, ровная тень).
- `01 / contact`: «Questions, ideas or a problem?» / «Let me know, and I'll try to help. Known bugs are listed there too.»
  + кнопка «Write to me →».
- Фон: одна пунктирная сетка графика на всю вкладку. Сверху (до `01 / tools`) «проигрываются» четыре линии в цветах
  чарта; перекрестие цепляется к ближайшей точке под мышью и проецирует её на оси с подписями (без мыши — само).
  Линии мягко гаснут перед `01 / tools`. Каждая точка, уходящая слева, отцепляется и улетает за край с хвостом,
  тут же выбегает у левого края внизу, бежит по строке сетки направо, уходит за правый край и влетает на график
  справа, присоединяясь к линии только после посадки.

## Contact (04) — в работе

- Форма прямо на странице (без отдельной кнопки):
  - тип `Bug / Question / Suggestion` (так и во «Входящих»: баг идёт в исправления, вопрос — в ответ или FAQ,
    предложение — в планы); продукт `UI Line Chart / UI Factory` (подставляется из `?product=`). Форма только про
    инструменты: варианта «Something else» нет, всё остальное — письмом на почту;
  - сообщение — обязательное, подпись меняется по типу: «what happened and how to reproduce it» (пример шагов в
    подсказке, отдельного поля для шагов нет), «your question», «your suggestion»;
  - подсказка над сообщением по типу: у бага — «check the known issues ↓», у вопроса — «check the FAQ ↓»
    (ссылка прокручивает к разделу), у предложения — нет;
  - только для бага: **версия пакета — обязательная**, выпадающий список выпущенных
    версий продукта, последняя выбрана по умолчанию (свободного ввода нет, чтобы не было опечаток); версия Unity — необязательное текстовое поле (версий слишком много для списка);
    вложение — png/jpg/txt до 5 МБ, кликом или перетаскиванием, ограничение написано у поля, ошибки размера и типа
    инлайн (лимит API Notion для бесплатного пространства — 5 МиБ на файл);
  - почта — по желанию; при пустой почте тихая строка: у бага «Without an email I can't ask you for details.»,
    у вопроса «Without an email I can only answer in the FAQ.», у предложения «Without an email you'll only see
    it in the changelog.»;
  - «Send →» и «or skip the form and email me at sxm.sxpxxl.dev@gmail.com».
- Почта: один общий адрес `sxm.sxpxxl.dev@gmail.com` на весь сайт вместо `sxm.tools@gmail.com` — по нику, а не по
  одному проекту (`sxm.sxpxxl@gmail.com` занят). Отдельный ящик, создан 2026-10-26, автор ведёт его напрямую.
  `sxm.tools@gmail.com` не удалять, пока на нём держатся логины (вероятно, YouTube-канал @sxm-tools, Unity ID и
  Asset Store, Pixabay), а его адрес записан в опубликованных версиях пакетов. «Write to me →» на SXM Tools и
  About me ведёт на вкладку Contact.
  Переезд (2026-10-31): YouTube-канал пересоздан на новом адресе; в Unity контакт организации заменён на новый,
  вход в Unity ID — личная почта автора, её менять не нужно; почту поддержки в Publisher Portal (Asset Store)
  задать сразу новую.
  - Необязательные поля — пунктирная рамка, обязательные — сплошная той же яркости. Варианты в прототипе: только
    пунктир; пунктир + необязательные тише (без заливки, подпись бледнее); пунктир + обязательные ярче (рамка и
    подпись светлее). Выбор открыт.
  - Заполненное необязательное поле теряет пунктир и выглядит как обычное (сплошная рамка, заливка, подпись
    в полную силу). Варианты: только сплошная рамка; рамка + зелёная галочка вместо слова «optional». Выбор открыт.
  - Ошибка пустого сообщения — инлайн. После отправки — строка `> send bug · ui-line-chart@0.9.14 ok` и благодарность
    «Thanks — I'll do my best to look into it. If you left an email, I'll reply there.» (без обещания прочитать
    каждое сообщение).
  - Список версий в прототипе — заглушка. На сайте — теги версий из репозитория пакета: та же GitHub Action, что
    забирает Known issues, читает теги через API GitHub (для закрытого репозитория — токен в секретах), и из них же
    берётся версия на бейдже. Поле Version в Notion не подходит: там бывают и запланированные версии.
    Тег ставится, когда версия вышла (для стора — после одобрения), поэтому фильтр не нужен.
- `04 / known issues`: фильтр по продукту (попадает в адрес); таблица Issue / Product / Version / Status;
  строки подсвечиваются и раскрываются (описание, обходной путь с шагами и кодом, «affects … · copy link»);
  исправленные свёрнуты в `fixed (n)`, счётчик учитывает фильтр, при нуле блок скрыт; «No open issues for this product».
- Статусы: Investigating (оранжевый), Planned (фиолетовый), Fixed (зелёный), Won't fix (серый).
- База Known issues: Title, Product (добавить), Status, Version, Workaround, Note; подробности — в теле страницы.
  Сюда попадают баги после разбора автором.
- `04 / faq` (после Known issues): вопросы, на которые автор решил ответить публично. Таблица Question / Product,
  строка раскрывается в ответ с «copy link»; «No questions for this product yet». Фильтр по продукту общий с
  Known issues: два ряда кнопок над разделами всегда показывают одно и то же. База FAQ в Notion: Question (заголовок),
  Product; ответ — в теле страницы. Вопросы в прототипе — заглушки.
- Предложения (Suggestion) не публикуются: остаются во «Входящих», а вошедшие в выпуск автор упоминает в списке
  изменений. Публичный roadmap — возможно позже, когда предложений станет много.
- Фон: «тишина» — неподвижное зерно и затемнение по краям.

## About me (05) — в работе

- Заголовок ABOUT ME, лид, текст слева, портрет справа, под текстом «Write to me →», LinkedIn, GitHub.
  На телефоне портрет стоит сразу после лида, перед текстом. На 700–880 px ряд кнопок занимает всю ширину
  под текстом и портретом.
- Портрет — квадрат по ширине своей колонки, не растягивается по высоте текста (иначе на 700–880 px он берёт
  ширину от высоты текста, вылезает справа и сжимает колонку с подписью `05 / about me`).
- Текст — черновой; нужен рассказ автора: опыт, кто он, почему делает инструменты.
- Фон: «лампа» — мягкий свет тянется за мышью; лупа появляется только над портретом (над текстом мешала читать).

## Metta Corpse (02) и Études (03) — заглушки

- Metta Corpse: цикл проектов о духовной стороне жизни автора (LoST, AB). Фон «мрак»: серый туман, падающий пепел,
  «дышащая» темнота по краям, без цвета. Нужны логотип (Affinity) и общая информация — уместность сейчас под вопросом.
- Études: пробы и эксперименты (Hanoi Tower). Фон «карандаш»: бумага в точку, линии, круги, почеркушки, штриховка,
  стопки дисков; ластик иногда стирает; при 14–18 фигурах лист очищается полосой и рисование начинается заново.
- У обеих вкладок позже будут свои логотипы вместо текстовых заголовков и собственный стиль.

## Общие правила

- Живые фоны: Canvas 2D, ~30 кадров/с, пауза на скрытой вкладке, статичный кадр при «уменьшить движение».
- Тексты сайта — английские, американское написание, от первого лица; без имён API в маркетинговых текстах.

## Как продолжить работу с прототипом

- Визуальный компаньон запускается напрямую через node (команды `bash …` запрещены глобальными настройками), в фоне:
  `BRAINSTORM_DIR=D:/rust-projects/persona/.superpowers/brainstorm/1382-1792925805
  BRAINSTORM_PORT_FILE=…/.superpowers/brainstorm/.last-port BRAINSTORM_TOKEN_FILE=…/.superpowers/brainstorm/.last-token
  BRAINSTORM_HOST=127.0.0.1 BRAINSTORM_URL_HOST=localhost
  node ~/.claude/plugins/cache/claude-plugins-official/superpowers/<версия>/skills/brainstorming/scripts/server.cjs --brainstorm-server-id=<случайный hex>`.
  Старая папка сессии используется повторно, поэтому прототип и картинки уже на месте, а порт и ключ прежние.
  Адрес с ключом — в `.superpowers/brainstorm/1382-1792925805/state/server-info`.
- Картинки в прототипе грузятся как `/files/<имя>` прямо из `content/` (без подпапок): `logo.png`, `avatar.png`,
  `chart-*.png`, `factory-*.png`. Источники — `Promo~\studio`, `Promo~\chart\frames`, `Promo~\factory\frames`.
- Новый экран — новый файл (`prototype-v11.html` …): сервер показывает самый свежий. Приложение при записи HTML
  открывает лишнюю вкладку `file://` — её закрывать и смотреть через вкладку сервера. Во время многошаговой правки
  в консоли остаются ошибки от промежуточных перезагрузок — проверять состояние уже после.
- Для проверок запуск пропускается событием клавиши (`keydown`), вкладки переключаются `go('<id>')`
  (`sxm`, `metta`, `etudes`, `contact`, `about`), запуск повторяется `replayBoot()`.
- Устройство `prototype-v20.html`: стили (оболочка, SXM Tools, карусель, Contact и Known issues, неиспользуемая
  светлая тема, запуск, телефон через container queries `@container stage`, форма); разметка
  `.stage > .px` (шапка `.bar`, страницы `#p-sxm`, `#p-metta`, `#p-etudes`, `#p-contact`, `#p-about`); скрипты по
  разделам: living backgrounds v2, music themes, boot, known issues, phone, contact form.
